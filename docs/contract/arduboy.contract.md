# Acceptance contract: Jet Fighters on the Arduboy (porting the machine)

Authored from `docs/prd/jet-fighters-arduboy.md` before decomposition. This
contract is what the tasks derived from it are graded against. Its sha256 is
recorded at freeze; a mid-run edit aborts the run rather than certifying
against a moved target.

The class is `interactive`, for one reason and a narrower one than v2's, v3's,
v3-entities' or v4's. Almost everything here is machine-checkable: the machine
has no hardware timer and no LFSR, it is deterministic given its inputs, and
`tools/probe/machine-probe.ts` already emits a trace format two cores can be
compared in. What a cold agent cannot judge is A12 - whether the re-laid-out
tube is legible on a 128x64 panel held in the hand. The PRD's decision 4 takes
a deliberate liberty with the tube's proportions, and the owner has agreed to
it in principle; whether it worked is a thing seen, not measured.

**This contract deliberately names no cadence figure.** `docs/prd/jet-fighters-v4.md`
is decomposed and unstarted, and it changes the missile's per-column time, the
squadron's step, the march note's length and the fraction of frames that blank.
A criterion below that quoted any of those would be certifying the Arduboy
against a ROM that is about to move. Every criterion instead requires a figure
to be *equal across the two cores at the same commit*, or to be read from the
constant that holds it current. That is what makes this contract survive v4
landing underneath it, and a criterion that acquires a millisecond figure during
the run has broken the property rather than tightened it.

**This contract licenses no gameplay change.** A rule that looks wrong on the
Arduboy is wrong on the web, and belongs in a ROM PRD. `asm/jetfighter.asm` is
read by this run and not written by it.

## What this contract is guarding against

### A rewrite wearing an emulator's clothes

The PRD's decision 1 is that the Arduboy interprets the ROM. The failure mode is
not an honest disagreement with that; it is a core that mostly interprets and
special-cases the two or three places where interpreting was hard, reaching the
right trace by a route that is not the machine. Such a build passes any test
written from the outside, because the trace is what was fitted to.

A9 is written against that rather than against correctness. Trace equality over
drives is necessary but not sufficient, because the drives are chosen by the
same person who wrote the core. What makes it a falsifier is the mutation
conjunct: a deliberately corrupted opcode handler must make a drive fail. A
suite that stays green when the core is broken was never testing the core, and
this is the cheapest way to find that out.

### A comparison of a thing with itself

The conformance harness runs two cores and diffs their traces. If the C++ side
replays a recorded trace, or reads its expectations from a fixture generated by
the TypeScript side and committed, the equality is vacuous and looks identical
in CI to the real thing. A9 requires both sides to run live in the same process
from the same ROM, and requires the harness to hold no committed trace fixture
at all. A checked-in golden trace is the shape this forbids, however convenient.

### A budget established by division

274 ATmega cycles per emulated instruction is 16,000,000 divided by 58,333. It
is arithmetic about two clocks, and it says nothing about what an interpreter
costs. The port either fits in it or the pace `v4` is establishing is lost on
this target, and that is the one thing in this PRD that can fail outright.

A8 requires the figure to be measured on the device over a minute of running,
and requires the report of where the cycles went to be committed. An estimate,
a figure from a host build scaled by a clock ratio, or a measurement over a
second are each a different way of not having done it. A8 is also why the order
in the PRD puts pacing before the on-target work: learning the budget does not
close is worth less after the renderer is finished than before.

### A generated file that has quietly become a source file

`rom.h` and `atlas.h` are the ROM and the tube, copied. This repo already
refuses hand-edited copies for atlas coordinates, video cadences and console
dimensions, and the reason transfers exactly: a hex table someone fixed by hand
is a second ROM that no longer has to agree with `asm/jetfighter.asm`.

A3 and A4 require regeneration to be byte-identical and CI to fail on a stale
header. The failure this catches is not malice - it is the afternoon where the
assembler output changes, the header is not regenerated, and both targets keep
passing their own tests while running different programs.

### The display read directly instead of through the sweep

The shortest path from emulated state to pixels skips the VFD scan: ask the
board which cells are on and draw them. It is faster, it is less code, and it
silently deletes the behaviour `v4`'s R2 exists to establish - the display going
dark while a note plays, which happens because the ROM stops sweeping and not
because anything says "blank".

A2 and A5 require the duty accumulator to be built and driven, and A9 requires
the blank intervals to appear in the Arduboy's trace at the same cycles as in
the TypeScript core's. A port that renders a correct-looking playfield with no
blanking has taken the shortcut, and the trace is where that shows.

### The blanking guarded at its cause and never at its effect

The four conjuncts above guard how the duty table is *filled*: from observed
writes, during the sweep, with unscanned intervals out of the denominator. All
four can hold in a port whose panel never goes dark.

On the web target the darkness is a second mechanism, and this contract did not
name it. `Display.isRefreshing()` compares the gap since the last drive against
`REFRESH_TIMEOUT_CYCLES`, and `Board.getLitSegments()` routes through
`getObservedFrame()`, which returns an **empty segment list** once that gap is
exceeded. The driver feeds that to the renderer every frame and the phosphor
decays to black. The denominator is how blanking stops corrupting the duties;
the empty list is how the tube goes dark.

A renderer triggered only on a closed sweep never sees it. The ROM parks the
sweep to bit-bang a note, no frame closes, no render fires, and the panel holds
the pre-note image for the whole note. Such a port is dark 0% of the time
against the 14-17% `vfd-appearance.md` section 5 measures and the floors
`jet-fighters-v4.md` R2 is doubling - and it passes a trace comparison, because
`tools/probe/machine-probe.ts` builds its snapshots from `getFrame()` and says
in its own comment why: "`getLitSegments()` answers the viewer's question
instead - what is on the glass at this instant - and the answer is nothing while
the ROM has the sweep parked to bit-bang the speaker."

So the trace format this contract adopts excludes the blink by design. A5 and A9
below carry the effect explicitly, and A12 asks the operator the question
`docs/contract/v3.contract.md`'s V12 asked and this contract had dropped.

### Game state outside the emulated RAM

`CLAUDE.md`'s rule holds on this target: score, jets, lives and skill are
nibbles the program put in RAM. The Arduboy adds one temptation the web page
does not have, and the PRD's decision 4 walks straight into it - the panel shows
the lever and skill positions, because the device has no case to look at.

That indicator is the case, not the game, and A5 requires it to read the input
layer's control state - A5 rather than A6, because the render site is where the
indicator's values are read, and A6 covers the translation of buttons into
contacts on the K matrix. An indicator fed from emulated RAM, or a skill value
cached in a C++ variable the ROM does not see, is state outside the machine.

## Drive surface

Tier-1 criteria are driven three ways, and which one a criterion uses is part of
the criterion:

- **Host**, for everything about the core's semantics: the C++ sources compiled
  for the development machine and run in the same process as the TypeScript
  core, with no AVR involved. This is what CI runs.
- **Build**, for the size budget: `pio run` and `avr-size` over the real
  firmware, which CI also runs.
- **Device**, for A8, A10 and A12: the flashed binary on the Arduboy over the
  CDC port. CI does not run these, and a criterion that says Device is not
  satisfied by a host result however equal.

`simavr` and `simulavr` are absent from Homebrew and no AVR instruction-set
simulator is in this plan. A criterion that reaches its observation through one
has changed the drive surface and fails.

Inputs reach the machine only by closing contacts on the K matrix, on both
sides. The no-poke check `docs/contract/v4.contract.md`'s F4 states applies
unchanged to every file under `arduboy/test/`, and to its C++ equivalent: the
core exposes exactly one method that writes machine state and it does not appear
in a conformance drive.

**Every bound is read at verification time from the constant or document that
holds it current**, per `docs/contract/v3.contract.md`'s rule. Which holds each:

| Bound | Held current in |
| --- | --- |
| Instruction rate | `CYCLE_HZ` in `src/machine/cpu/tms1370/timing.ts` |
| Sweep length and lit-segment duty | `SWEEP_INSTRUCTIONS` and `LIT_SEGMENT_DUTY` in `src/machine/board/tms1370-cadence.ts` |
| Blank threshold - how long unscanned before the tube reads dark | `REFRESH_TIMEOUT_CYCLES` in `src/machine/board/tms1370-cadence.ts` |
| Dark-frame fraction of the real unit | `docs/evidence/vfd-appearance.md` section 5 |
| Power-on RAM contents | `RAM_POWER_ON_FILL` in `src/machine/board/power.ts` |
| Program and page ceilings | The assembler listing, 2048 words and 64 words a page |
| Pin allocation | `src/machine/cpu/tms1370/ports.ts` |
| Segment geometry, grid and plate per cell | `src/machine/tube/atlas.json` |
| Usable flash after the bootloader | Read off the device in A10; until then PlatformIO's `leonardo` figure, the smaller of the two |

**How to run what the criteria name.** The firmware builds with `pio run` from
`arduboy/`. Host conformance is `npm run arduboy:test`. The assembler listing is
`npx vite-node tools/tmsasm/cli.ts asm/jetfighter.asm --listing <path>`. Device
criteria need the Arduboy attached and enumerating; the port it presents is not
a fixed name and is discovered, not typed.

## Floors

Carried from `docs/contract/v3-entities.contract.md` and `v4.contract.md`, and
restated because this run adds a second consumer of both:

- **The assembled program stays inside 2048 words and every page inside 64.**
  This run does not write `asm/jetfighter.asm` at all, so the floor is a check
  that it did not: the listing's word and page totals at HEAD equal those at
  BASE.
- **The TypeScript target is not regressed to make the port easier.** `npm run
  lint`, `npm test` and `npm run build` are green over the whole tree, with no
  test newly skipped or newly marked `it.fails` against BASE. A conformance
  failure resolved by loosening an assertion on the TypeScript side has moved
  the reference rather than fixed the port.
- **`src/machine/` still touches no DOM and owns no clock.**
  `src/app/clock-owner.test.ts` and the dependency-boundary test are green. The
  port reads these modules; it must not have earned its access by relaxing them.
