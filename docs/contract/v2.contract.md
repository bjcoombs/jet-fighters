# Acceptance contract: Jet Fighters v2 (interactive/visual class)

Authored from `docs/prd/jet-fighters-v2.md` before decomposition. This is the
contract the cold exit verifier executes against the assembled v2 product. It is
frozen (sha256 recorded) before any v2 task is decomposed; a mid-run edit aborts
the run rather than certifying against a moved target.

The class is `interactive`, so the machine tiers are deliberately thin. Tier-1
covers only what a cold agent can drive and observe with no human and no
browser; tier-3 covers the perceptual residue - the thing v1 actually failed at,
which no cold agent can judge.

## Why v1's contract would have passed a facade

v1 shipped 100% merged and was, in the owner's verdict, a facade: it rendered a
convincing scope and scored points, so every process signal read "done". The
lesson encoded here is that **each tier-1 criterion must be falsified by an
artifact that merely looks finished**. Criteria are therefore written to lead
with a positive requirement that absence cannot satisfy. V6 is the sharpest
example: "the v1 modules are gone" is satisfiable by an empty repo, so V6
requires the machine code to be *present in the built bundle* as well.

## Drive surface (a v2 deliverable)

Tier-1 criteria are driven in Node, not a browser, because the v2 machine layer
(CPU, board, speaker) is pure TypeScript with no DOM dependency - the same
property the PRD relies on for its headless spectral tests. v2 must therefore
ship a probe harness:

`tools/probe/machine-probe.ts`, runnable as
`npx vite-node tools/probe/machine-probe.ts [--cycles N] [--input SPEC] [--emit-edges]`,
writing a single JSON object to stdout:

```
{
  "romWords":     int,           // assembled program words
  "ramNibbles":   int,           // RAM high-water mark
  "strobeCycles": int,           // machine cycles executed
  "gridsStrobed": [int],         // distinct D-port grids driven, expect 0..9
  "snapshots": [                 // always: [0] is the baseline, then one per --input
    { "atCycle": int, "litSegments": [[grid, plate, duty], ...] }
  ],
  "speakerEdges": [[cycle, level], ...]   // D14 transitions, when --emit-edges
}
```

`snapshots[0]` is a **baseline** taken once the machine has completed at least one
full display sweep and before any input is injected; it is always present, even
when the probe is run with no `--input`. Each `--input` event appends one further
snapshot taken after that event has been strobed in. So a run with no input
yields exactly one snapshot, and a run with one input yields two.

`--input SPEC` takes `name=value@cycle` (e.g. `lever=up@200000`, `fire@200000`)
and injects the control through the strobe matrix exactly as the case wiring
does - not by poking game state.

## Where the v1 audio reference lives

V5 compares the emulated speaker output against measurements taken from the
owner's recordings of the real unit during v1. Those numbers currently survive
only as comments in `src/audio/audio.ts` - a module V6 requires v2 to delete.
The measurements must therefore be extracted to a durable artifact,
`docs/evidence/audio-reference.md`, before that deletion (PRD R7; Task Master
task 10). V5 states the numeric band inline as well, so the criterion stays
deterministic even if the artifact's wording drifts.

The thresholds in V1 and V2 (>= 200 assembled words, >= 100 passing tests) are
floors chosen to be far below a real HMCS44 core and 2 KB game program, and far
above any stub. They exist so a skeleton cannot satisfy the criterion.

```yaml
class: interactive
criteria:
  - id: V1
    tier: 1
    action: "Run: npm ci && npx vite-node tools/hmasm/cli.ts asm/jetfighter.asm --listing /tmp/jf.lst ; capture the exit code and read the listing file."
    observation: "Exit code is 0; the listing's highest assembled address is <= 2047 and its reported RAM high-water mark is <= 160 nibbles; the listing contains at least 200 assembled instruction words, each a 10-bit opcode value. A missing assembler, a missing asm/jetfighter.asm, or an overflow past 2048 words fails."
  - id: V2
    tier: 1
    action: "Run: npm ci && npm test -- --run --reporter=json > /tmp/jf-tests.json ; parse the JSON summary."
    observation: "numFailedTests is 0 and numPassedTests >= 100, and the passing set includes tests located under src/machine/cpu/ that exercise the HMCS40 instruction set. Zero tests, absent CPU tests, or any failure fails the criterion."
  - id: V3
    tier: 1
    action: "Run: npx vite-node tools/probe/machine-probe.ts --cycles 400000 ; parse the JSON on stdout."
    observation: "strobeCycles > 0; gridsStrobed contains every value 0 through 9 (the full display sweep); and snapshots[0].litSegments is non-empty with at least one segment whose duty is strictly between 0 and 1, proving PWM accumulation rather than a static on/off write. The CPU is executing our ROM and driving the tube."
  - id: V4
    tier: 1
    action: "Run: npx vite-node tools/probe/machine-probe.ts --cycles 400000 --input lever=up@200000 ; compare the pre-input and post-input snapshots in the JSON."
    observation: "Both snapshots are present and their litSegments sets differ in the launcher lane region - the launcher lever moves lanes in response to input strobed through the matrix. Identical snapshots, or a missing second snapshot, fails."
  - id: V5
    tier: 1
    action: "Run: npx vite-node tools/probe/machine-probe.ts --cycles 400000 --input fire@200000 --emit-edges ; reconstruct the D14 waveform from the edge stream and take its FFT."
    observation: "speakerEdges is non-empty and contains transitions after cycle 200000; the dominant frequency of the reconstruction falls within 1480-1632 Hz (the v1 measured band for the missile-fire blip) and the burst is shorter than 150 ms; and docs/evidence/audio-reference.md exists and records that same band under missileFire.dominantHzRange with its provenance. Computed from the pin edge stream alone, with no audio event API involved."
  - id: V6
    tier: 1
    action: "Run: npm run build ; then search the emitted dist/ bundle for machine-layer identifiers, read package.json, and list src/."
    observation: "All four hold: build exits 0; the dist/ bundle contains the HMCS44 core and tube-renderer code originating from src/machine/; package.json declares zero runtime dependencies; and no src/game/, src/render/, or src/audio/ module remains. An empty, missing, or unbuilt artifact fails on the first two conjuncts."
  - id: V7
    tier: 3
    action: "Operator launches the built site, selects skill 1, and plays it beside the reference gameplay video in docs/evidence/ and the physical CGL unit."
    observation: "Stepping rhythm, PWM flicker and brightness shimmer, cyan/red phosphor regions under the filter overlay, segment shapes, and sound timing are recognisably the 1979 Jet Fighters unit rather than an imitation of it. Human-mandatory: a cold agent structurally cannot observe this. Recorded via the operator's observed output pasted into the completion record."
```
